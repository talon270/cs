Running total, running best

The problem says sum, total, average, maximum, minimum, how many, or count.

One variable outside the loop, updated once per element inside it. Initialise it from the first element for max and min, not from 0 — an array of negative numbers has no element above zero and the answer comes out 0.

int best = a[0];

    if (a[i] > best) best = a[i];

Second largest, without sorting

Second largest, runner-up, next best.

Two variables, updated in the right order: when a new best arrives, the old best becomes the second. Sorting first also works and costs O(n log n) to answer a question that needs one pass.

int best = INT_MIN, second = INT_MIN;
for (int i = 0; i < n; i++) {
    if (a[i] > best) { second = best; best = a[i]; }
    else if (a[i] > second && a[i] != best) second = a[i];
}

Two indices walking towards each other

Reverse, palindrome, swap ends, rotate by one.

One index at each end, swap, step both inward, stop when they meet. The loop runs n/2 times, not n — running it n times reverses the array and then reverses it back.

Test a number by walking its divisors

Prime, perfect number, Armstrong number, factors of, divisible by.

One loop from 2 to n/2 (or to √n for primality), accumulating divisors or testing remainders. Stop at √n and say why: a divisor above it implies one below it, so the second half of the loop cannot find anything the first half missed.

int is_prime(int n) {
    if (n < 2) return 0;
    for (int d = 2; d * d <= n; d++)
        if (n % d == 0) return 0;
    return 1;
}

Outliers, anomalies, clean the extreme values.
