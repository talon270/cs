One dtype per arraywhy it is fast

Every element has the same type and sits in one contiguous block of memory, so the maths runs in compiled code instead of a Python loop. That is the whole performance story.

np.array([1, 2, 3]).dtype        # int64
np.array([1, 2.5]).dtype         # float64 - promoted
a.astype('float32')              # convert

Vectorised mathsno loops

a * 2            # every element
a + b            # element by element
a ** 2   np.sqrt(a)   np.log(a)
a > 2            # array of True/False

# the slow way you should never write:
[x * 2 for x in a]

An operation on a whole array replaces the loop. This is the single habit that separates fast pandas code from slow pandas code.

Broadcastingshapes that differ

a = np.array([[1, 2, 3],
              [4, 5, 6]])     # shape (2, 3)
a + 10              # scalar stretched over everything
a + np.array([1, 0, 1])   # (3,) stretched down the rows
a / a.sum(axis=1, keepdims=True)   # row shares

Dimensions are matched from the right; a dimension of 1 is stretched. Mismatched shapes raise instead of guessing.

Aggregatingaxis

a.sum()            # everything -> one number
a.sum(axis=0)      # down the columns
a.sum(axis=1)      # across the rows
a.mean() a.std() a.min() a.max()
a.argmax()         # position of the largest
a.cumsum()

axis=0 means “collapse the rows”, giving one value per column. It is the same in pandas.

Indexingslices and masks

b[0, 1]     # row 0, column 1
b[:, 0]     # every row, first column
b[1, :]     # second row

a[mask]            # only the matching values
a[(a > 2) & (a < 8)]     # brackets are required
a[a > 2] = 0             # assign through a mask

Use & | ~ with arrays, never and or not. Python's keywords need a single True/False and will raise.

Conditional valueswhere / select

    [a < 0, a == 0, a > 0],           # conditions
    ['neg', 'zero', 'pos'],           # results
    default='?')

Setting valuesassignment

df.loc[df.sales < 0, 'sales'] = 0      # correct way
df.loc[0, 'city'] = 'Delhi'
df['flag'] = df['sales'] > 100

df[df.sales < 0]['sales'] = 0          # ChainedAssignmentError
                                       # nothing is written

Assign through a single .loc, never through two chained brackets — the second bracket is always a copy.

Copies and viewscopy-on-write

small = df[df.city == 'Pune']   # behaves as its own copy
small['bonus'] = 1              # changes small, never df

df[df.city == 'Pune']['sales'] = 0   # writes to a temporary
                                     # and is thrown away
df.loc[df.city == 'Pune', 'sales'] = 0    # the correct form

Since pandas 3.0 Copy-on-Write is the rule: every result behaves like its own copy, so editing a slice can never reach back into the original. The old SettingWithCopyWarning went with it, and so did the defensive .copy() people added to silence it.

On pandas 2.x the same chained write warns instead, and may or may not go through. Assigning through a single .loc is correct on both.

Series in, Series outalignment

b = pd.Series([10, 20], index=['y', 'z'])
a + b        # x NaN, y 12, z NaN

Arithmetic lines up on the index, not the order. Mismatched labels produce NaN rather than a silent shift — that is a feature.

    return (df
        .rename(columns=str.lower)
        .drop_duplicates('id')
        .assign(date=lambda d: pd.to_datetime(d.date, errors='coerce'),
