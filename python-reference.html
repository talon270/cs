Run it

Getting from a blank file to a running program, and reading the message when it goes wrong.
01

Install and checkterminal

Python 3 is the only Python. Type this in a terminal (Command Prompt, PowerShell, or Terminal):

python3 --version     # mac / linux
python --version      # windows
# Python 3.14.7  <- you want 3.10 or newer

No version number? Install from python.org, tick “Add Python to PATH” on Windows.

Run a filethe normal way

Save text in a file ending in .py, then run it. The file is your program; Python reads it top to bottom, once.

python3 hello.py
python3 hello.py arg1 arg2   # pass arguments in

The REPLscratchpad

Run python3 with no file and you get a prompt that evaluates one line at a time. Perfect for testing a single idea. exit() or Ctrl-D leaves.

>>> 2 + 2
4
>>> len('hello')
5

Your first programhello.py

print("Hello, world!")

name = input("Your name? ")
print("Hi", name)
print(f"{name} has {len(name)} letters")

print writes to the screen. input stops and waits for the user to type a line, and hands it back as text.

Commentsnotes to humans

# everything after a hash is ignored
x = 5  # end-of-line note

"""A triple-quoted string on its own line is
not technically a comment, but it is the
normal way to write a long note."""

Python has no /* */ block comment. Most editors comment a block with Ctrl-/.

Indentation is syntaxthe big one

Other languages use { } to group lines. Python uses indentation — 4 spaces per level. Lines indented the same amount belong to the same block.

if True:
    print('inside')   # 4 spaces = inside the if
print('outside')      # back to margin = after it

Never mix tabs and spaces. Set your editor to insert 4 spaces for Tab.

Reading an errortraceback

Python prints the failure from the outside in. Read it bottom up: the last line is what went wrong, the line above is where.

Traceback (most recent call last):
  File "hello.py", line 4, in &lt;module&gt;
    print(total / count)
                 ~~~~~~^~~~~~~
ZeroDivisionError: division by zero

Here: file hello.py, line 4, dividing by a count that was 0.

The three errors you will hit firstfirst week

SyntaxErrorA typo Python cannot even parse. Usually a missing : , ) or quote — check the line above the one reported.
IndentationErrorYour spacing does not line up.
NameErrorYou used a name you never assigned, or misspelled it.

Two modes, one languagemental model

A script is a saved list of instructions. The REPL runs them one at a time and prints each result automatically. In a script, nothing is shown unless you print it.

Every value works in an if. These are falsy; everything else is truthy:

Mutable vs immutablewhy it matters

Immutable (int, float, str, tuple, bytes, frozenset) can never be changed — operations return a new value. Mutable (list, dict, set, most objects) change in place, and every name pointing at them sees the change.

a = [1, 2]
b = a          # same list, two names
b.append(3)
print(a)       # [1, 2, 3]  <- surprise

b = a.copy()   # now independent

Iterables and iteratorshow for works

An iterable can be looped over (list, str, dict, file, range). An iterator is the thing that actually walks it, producing one value at a time and remembering where it stopped.

it = iter([1, 2])

Generatorsyield

def countdown(n):
    while n > 0:
        yield n        # hand one value back, PAUSE here
        n -= 1

for x in countdown(3):     # 3, 2, 1
    print(x)

g = countdown(3)
next(g)    # 3  -- runs until the next yield

yield makes a function produce a stream. Nothing runs until you ask for a value, and only one value exists at a time — so a generator can describe a billion items, or an endless one, in constant memory.

Why lazy mattersmemory

sum([n*n for n in range(10**7)])   # builds 10M items
sum(n*n for n in range(10**7))     # builds none

def read_big(path):
    with open(path) as f:
        for line in f:        # files are lazy too
            yield line.strip()

yield from and sendadvanced

def chain(a, b):
    yield from a      # delegate to another iterable
    yield from b

def acc():
    total = 0
    while True:
        total += yield total   # receives values
g = acc(); next(g); g.send(10)    # 10

A class with hooksworked example

class Money:
    def __init__(self, amount):
        self.amount = amount
    def __repr__(self):
        return f'Money({self.amount})'
    def __str__(self):
        return f'${self.amount:.2f}'
    def __eq__(self, other):
        return self.amount == other.amount
    def __hash__(self):
        return hash(self.amount)
    def __add__(self, other):
        return Money(self.amount + other.amount)
    def __lt__(self, other):
        return self.amount < other.amount

m = Money(5) + Money(3)
print(m)            # $8.00
sorted([Money(2), Money(1)])

A decorator is a wrapperstep by step

def shout(func):              # takes a function
    def wrapper(*args, **kwargs):
        result = func(*args, **kwargs)
        return result.upper()     # add behaviour
    return wrapper                # gives one back

def greet(name):
    return f'hi {name}'

greet = shout(greet)    # wrap it manually

# @ is shorthand for exactly that line:
@shout
def greet(name):
    return f'hi {name}'

greet('ada')      # 'HI ADA'

Do it properlyfunctools.wraps

import functools

def timer(func):
    @functools.wraps(func)        # keeps __name__, __doc__
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        try:
            return func(*args, **kwargs)
        finally:
            print(f'{func.__name__}: {time.perf_counter()-start:.3f}s')
    return wrapper

@timer
def slow():
    time.sleep(1)

Without @wraps, the decorated function reports itself as wrapper and loses its docstring.

Decorators with argumentsone more layer

def repeat(times):            # takes the argument
    def decorator(func):      # takes the function
        @functools.wraps(func)
        def wrapper(*a, **kw):
            for _ in range(times):
                r = func(*a, **kw)
            return r
        return wrapper
    return decorator

@repeat(times=3)
def ping(): print('ping')

Async & concurrency

Doing several things at once — and the one rule that decides which tool to use.
17

Pick the right tooldecide first

Waiting on network or diskasyncio or threads — the work is idle time, so overlap it
Heavy CPU mathsmultiprocessing — separate processes, real parallelism
One slow thing, simple codejust do it in order

The GIL (global interpreter lock) means only one thread runs Python bytecode at a time. Threads still help when the work is waiting, not computing; processes sidestep it entirely.

Python 3.14 officially supports a free-threaded build with no GIL (python3.14t). On a normal build the rule above still holds, so write for it.

How Python manages memoryunder the hood

Every value is an object on the heap. Names are labels pointing at objects. Python counts how many labels point at each object and frees it at zero; a cycle collector catches objects that only reference each other.

a = b = 256
a is b                  # True: small ints are cached
x, y = 'ab'*500, 'ab'*500
x is y                  # False: no such luck
x == y                  # True: compare VALUES

Speeding things upin order

  • Measure first: time.perf_counter, timeit, cProfile.
  • Pick a better structure: set/dict lookup instead of scanning a list.
  • Use built-ins — sum, sorted, map run in C.
  • Cache with @functools.cache.
  • Move array maths to numpy.
  • Only then reach for concurrency or another language.

How to actually fix a bugmethod

  • Read the last line of the traceback. It names the problem.
  • Find the line above it in your file, not the library's.
  • Print the values just before that line — the bug is usually in what the data is, not what the code says.
  • Shrink it: reproduce with the smallest possible input.
  • Change one thing at a time.

PEP 8 in briefhouse style

  • 4 spaces per indent, never tabs.
  • snake_case for functions and variables, CapWords for classes, UPPER for constants.
  • Lines under ~88 characters.
  • Two blank lines between top-level defs, one between methods.
  • Spaces around operators and after commas; none inside brackets.
  • Imports at the top: standard library, third party, then yours.
  • One statement per line.
